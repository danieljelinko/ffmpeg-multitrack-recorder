# Decisions

| Date | Title | Context | Decision | Consequences |
|---|---|---|---|---|
| 2025-11 | Abandon official-recorder-via-Jicofo path | Custom JVB/Jicofo builds to drive `jitsi-multitrack-recorder`; Jicofo gates recording on Jibri availability, never opens the JVB→recorder WebSocket | Drop this path (kept in archived `_jitsi-multitrack-recording`) | Established that Jicofo/Jibri is the blocker; pivoted away from Jicofo entirely |
| 2025-11 | Abandon custom FFmpeg RTP forwarder | slixmpp bot requested RTP forwarders via Colibri **v1** IQ; JVB 2.3.x returns `service-unavailable` | Drop the Colibri-v1 forwarder approach | XMPP/MUC bot infra kept and reused; needed a v2 mechanism |
| 2026-02-11 | **Core mechanism: JVB Colibri2 REST `connects`** | JVB exposes `PATCH /colibri/v2/conferences/{meetingId}` accepting a `connects` array | Controller drives JVB directly to open a MediaJSON WebSocket to the official recorder, **bypassing Jicofo/Jibri** | The whole recorder works without Jibri; ties us to the `connects` REST contract (re-checked each Jitsi upgrade) |
| 2026-02-11 | Audio via JVB, video via headless browser | JVB `connects` supports audio only (`Video` throws in JVB source) | Per-participant audio through JVB; **composite** video via a Playwright headless-browser participant | Audio is true multitrack; video is composite-only, heavier (Chromium) |
| 2026-02-14 | E2E via synthetic audio | Need deterministic, real-participant tests | pytest + Playwright, unique Web-Audio oscillator frequency per participant | Reproducible proof without human speakers |
| 2026-07-21 | Home under `~/Work/tools/`, dev-context + L4 | De-archiving into the tools ecosystem | Move here, apply dev-context rules, add L4 docs + `justfile` | Repo is now a first-class, agent-legible tool |
| 2026-07-21 | Two-baseline version policy | Known-good is `stable-10590`; want the newest that works for deployment | Prove pinned first, then attempt latest; keep pinned `.env` as fallback | Never lose the working baseline to a failed upgrade |
| 2026-07-21 | Controller chowns finished recordings to host user | Recorder/controller run as root over the bind mount → recordings land `root:root`, blocking host-side post-processing/backup/cleanup | Chown at the **controller finalize** (last writer: after dir rename + metadata + `_rename_mka_tracks`), recursively to configurable `HOST_UID:HOST_GID`; guarded (no-op unless running as root with both ids set). Logic isolated in dep-free `fs_ownership.py` for unit-testing | Single chown point covers the whole tree incl. the recorder-written MKA; needs `HOST_UID/GID` set per host (default `1000:1000`); no host-side privilege/sudo needed for downstream tools |
